# 授权与开发边界

## 读取门槛

默认只使用当前对话和 Carpe Diem 自己的本地状态。读取额外来源前说明：为什么需要、准确目标、只读范围、有效期。用户没有授权时使用现有证据继续或标记未知。

不得读取或保存 API Key、Token、密码、未授权目录、完整私人材料、完整聊天、源码副本或隐藏推理。

## 写入门槛

- 个人画像：先展示候选 Diff，用户确认后调用 `state apply`。
- 项目事件：先展示摘要、阶段变化和下一步，确认后调用 `project event`。
- 正式计划：逐章确认，整体批准后才写计划和交接文件。
- 计划修改：先展示文件 Diff，再获得单独确认。
- `.gitignore`：展示新增规则；用户拒绝时改用用户级项目状态位置。

## Track 只读合同

Track 只允许读取 Git 元数据、已有测试或 CI 结果、用户授权的 Issue 状态和正式计划。保持工作区原样：

- 不编辑、创建或删除业务源码；
- 不运行项目测试或未知脚本；
- 不提交、推送、切换分支或清理工作区；
- 不创建、关闭或修改 Issue；
- 不把发现的问题直接修复。

用户要求实现时，说明 Carpe Diem 已进入 Track 边界，输出给开发 Agent 的任务、范围和验收要求。用户可以结束 Carpe Diem 后另行启动开发工作流。

## 失败与停止

状态损坏、权限不足、证据不可用或历史不连续时停止相关动作，保留已有数据并如实报告。验证不足时使用“未知”或“未验证”，不以推断补齐证据。
