# 实战模式：Claude Code 最佳实践

> 来源：Anthropic 工程博客
> 蒸馏日期：2026-08-30

## 问题本质

开发者使用 AI Coding Agent 时常见的误区：给太少上下文、期望一次完美、不检查输出等。这导致 AI 生成的代码质量不稳定，需要反复迭代，反而降低了开发效率。

## 关键洞察

- **给 Agent 足够的上下文比调整 Prompt 技巧更重要**：将项目结构、技术栈、编码规范、相关文件一次性提供给 Agent，让它理解全景再动手，效果远优于逐轮补充。
- **分步验证而不是一次性完成任务**：将大任务拆解为多个小步骤，每步完成后检查中间结果，及时发现偏差并纠正，避免大范围返工。
- **明确"完成"的定义和验收标准**：在任务开始前就定义好什么是"完成"——包括测试通过、代码风格一致、文档更新等维度。
- **使用版本控制管理 Agent 的产出**：Agent 的每次修改都应通过 Git 提交管理，方便回滚和对比差异，而不是在同一个文件上反复覆盖。
- **让 Agent 迭代自己的输出**：要求 Agent 先输出方案，自行审查和改进，再提交最终版本，形成自检循环。
- **为 Agent 设计"安全网"**：在关键操作前加入确认步骤（如 lint、类型检查、测试），防止 Agent 做出破坏性修改。

## 对 Carpe Diem 用户的启发

### Discover 阶段

这个模式告诉用户：一个好的 AI 项目通常是从"给 AI 明确的上下文和验收标准"开始的。如果你的项目想法可以拆解为清晰的输入→处理→输出，那它就有很好的 AI 适配性。在 Discover 阶段，重要的是识别出那些"边界清晰、可验证"的任务，而不是模糊的"帮我写好一点"。

### Validate 阶段

验证一个 AI 项目是否可行的标准：
- **能否定义清晰的输入输出？** 输入文件的格式、数量、来源是否明确？输出结果是否可被客观检验？
- **错误容忍度是多少？** 某些场景（如代码生成）允许人工修正，某些场景（如金融计算）接近零容忍。
- **是否需要人工在循环中（Human in the loop）？** 关键决策点是否设定了人工审核节点？
- **验证周期多长？** 能否在 Agent 完成一个子任务后立即验证，而非等到全部完成才检查？

### Plan 阶段

规划 AI 项目时需要考虑：
- **上下文窗口限制**：任务规模和复杂度是否在模型上下文窗口之内？是否需要分阶段输入？
- **错误处理策略**：Agent 出错时如何降级——重试、跳过、报错通知人工处理？
- **渐进式验证方案**：设定里程碑检查点，每完成一个子任务自动验证输出质量。
- **人工审核节点**：在关键决策点（如数据库变更、生产环境部署）设置人工确认环节。
- **回滚机制**：确保 Agent 的每次修改都能通过版本控制回退，降低风险。

## 反向提醒

这个模式不适合：
- **需要 100% 准确率的场景**：如医疗诊断、法律判决、飞行控制系统等，AI 的输出必须经过严格的人工复核，Agent 的自主性应被大幅限制。
- **输出需要完全原创的创意工作**：如艺术创作、品牌命名、核心文案等，AI 更适合作为灵感助手而非决策者。
- **高度依赖隐性知识的领域**：行业经验、企业文化、人际关系等难以显式编码的上下文，Agent 无法充分理解，容易产生偏离预期的输出。
- **安全敏感的基础设施操作**：直接在生产环境执行数据库迁移、权限变更等操作，不应由 Agent 自主执行。
