# Architecture Decision Records (ADR)

> 架构决策记录（ADR）用于记录项目中的关键架构决策，包括决策背景、方案选择、影响后果和替代方案。

## 用途

- **记录决策历史**：每个 ADR 记录一次关键决策，包括为什么选这个方案、放弃了哪些方案。
- **降低认知负载**：后续开发 Agent 无需重新讨论已确定的决策，可直接查阅 ADR。
- **保持一致性**：新加入的 Agent 或开发者可以通过 ADR 快速理解项目的架构取舍。

## 命名规范

每个 ADR 文件按以下格式命名：

```
docs/adr/{编号}-{简短标题}.md
```

- **编号**：三位数序列号，从 `001` 开始，按时间顺序递增
- **简短标题**：小写 + 连字符，如 `use-postgresql-as-primary-database`

示例：`docs/adr/001-use-postgresql-as-primary-database.md`

## 状态说明

每个 ADR 都有一个状态，表示其生命周期阶段：

| 状态 | 含义 |
|------|------|
| 已提议 | 决策已提出，正在讨论中 |
| 已接受 | 决策已被接受并实施 |
| 已弃用 | 决策已被弃用，不再适用 |
| 已替代 | 决策已被新的 ADR 替代 |

## 查看方式

- 按编号顺序查看：`ls docs/adr/ | sort`
- 查看最新决策：`ls -t docs/adr/ | head -5`
- 查看所有已接受决策：`grep -l "已接受" docs/adr/*.md`

## 与 project-plan.md 的关系

`project-plan.md` 中的"关键决策记录"章节提供决策摘要，ADR 文件提供完整背景和替代方案分析。两者互补：计划文件用于快速浏览，ADR 文件用于深度理解。
