# 行为卡：安全设计

> 触发信号：Plan 阶段涉及外部输入、敏感数据、身份或权限边界
> 证据编号：WD-P9-04

## 问题本质

安全不是上线前附加的扫描。需要先知道保护什么、信任边界在哪里、失败会造成什么影响，再把最小控制放进设计。项目小只会改变控制强度，不会让基本安全边界消失。

## 触发条件

- 系统处理凭据、个人数据、付款、文件或第三方回调；
- 用户说“项目小，安全以后再说”；
- 只有认证，没有对象级授权和租户隔离；
- 输入校验只放在客户端或网关，领域规则无人负责。

## 行为指导

1. **画出资产与信任边界**：列出敏感数据、主体、入口、外部依赖、权限和最坏影响；只对真实风险设计控制。
2. **最小权限并逐次校验授权**：每个用户、服务和密钥只获完成任务所需权限；认证不等于有权访问具体对象。
3. **分层校验输入**：在外部边界尽早做类型、长度、格式和允许值校验；在领域层校验业务语义、状态转换和权限。客户端校验只改善体验，不能替代服务端。
4. **采用成熟原语**：密码存储、会话、加密、令牌和密钥管理使用维护良好的标准库或平台能力，不自行设计算法。
5. **设计安全默认和秘密边界**：默认拒绝、最小暴露、秘密不入仓库/日志、敏感错误不回显；为依赖和密钥准备轮换路径。
6. **按风险验证和响应**：定义安全测试、依赖检查、日志留痕、撤销/隔离/恢复和通知责任。高风险系统交给合格人员复核。

## 不适用场景

- 没有“完全不需要安全”的代码；纯本地、无真实数据的学习原型只需缩小控制范围；
- 本卡不能替代威胁建模、渗透测试、隐私评估或法律意见；
- 紧急修复可以压缩流程，但不能跳过秘密保护、授权和事后复核；
- 收集真实用户数据前，必须重新评估原型边界。
