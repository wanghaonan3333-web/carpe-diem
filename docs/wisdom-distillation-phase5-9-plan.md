# Carpe Diem Phase 5–9 智慧蒸馏执行计划

> Phase 5–9 是蒸馏工作批次，不是 Carpe Diem 新增的运行阶段。
> 当前状态：22 张候选卡均已实现并完成一手来源核验。

## 一、复核结论

原批次在主题选择上有效：补齐了验证、协作、产品、工程和反模式。但“卡片创建完成”不能等同于“蒸馏完成”，原方案还存在四个系统性问题：

1. 运行时不露来源被误解为研究层也不保留出处；
2. 固定卡片数量、触发数量和步骤数量鼓励填充；
3. 阶段整批加载导致上下文膨胀和近邻卡互相抢占；
4. 若干固定比例、时限和绝对断言没有一手依据。

本批次改用以下验收链：

`候选 → 一手核验 → 忠实转译 → 去重分工 → 场景测试 → 接受并路由`

详细方法见 `docs/wisdom-distillation-guide.md`，逐条证据见 `references/wisdom/phase5-9-evidence-register.md`。

## 三、运行时路由

- 当前阶段只缩小候选目录；
- 必须有来自对话或状态的具体触发信号；
- 每轮最多一张主卡，只有职责互补时再加一张辅卡；
- 优先级：安全/授权边界 > 阶段门槛 > 明确触发 > 辅助优化；
- 行为卡不能覆盖用户确认、阶段转换或 Track 只读边界；
- 无强信号、卡片冲突或建议不改变下一步时，不加载。

路由回归判例位于 `references/wisdom/mentors/routing-acceptance-cases.json`。

## 四、多人生产方式

### 作者职责

- 只修改自己负责的卡片；
- 提交证据 ID、精确来源、原始主张摘要、转译和边界；
- 提供正向、近邻、反向和风险场景；
- 不修改共享 README、SKILL、manifest 或总结。

### 集成者职责

- 审核来源忠实度和固定阈值；
- 执行近邻卡重叠检查；
- 维护共享索引、路由、manifest、版本和总结；
- 运行结构、重复、证据和场景校验；
- 可以合并或拒绝卡片，不以候选数量作为完成指标。

## 六、停止条件

本批次不继续按数量扩卡。只有真实运行中出现以下证据才新增候选：

- 用户在现有卡片覆盖外反复卡在同一决策；
- 现有阶段指南无法给出安全且具体的下一步；
- 新来源提供了会改变行为、且无法合并进现有卡的独特机制。

否则优先改进来源核验、路由和现有卡片边界。
